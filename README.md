# FPGA-Based Digital Arithmetic and Combinational Logic Design

A Verilog HDL project implementing fundamental arithmetic and combinational logic circuits, with FPGA constraints, simulation testbenches, and implementation reports using Xilinx ISE.

## Overview

This project explores RTL design and FPGA implementation of arithmetic circuits, code conversion, and magnitude comparison. It includes Verilog source modules, UCF pin constraints, functional simulation testbenches, and supporting FPGA design reports.

## Designs Implemented

| Module                     | Description                                                         |
| -------------------------- | ------------------------------------------------------------------- |
| 4-bit Adder                | Adds two unsigned 4-bit inputs and produces a 5-bit result          |
| 4-bit Subtractor           | Performs subtraction on two 4-bit inputs                            |
| Full Adder                 | Computes sum and carry from three 1-bit inputs                      |
| Binary-to-Gray Converter   | Converts an 8-bit binary value into Gray code                       |
| 2-bit Magnitude Comparator | Compares two 2-bit values for equality, greater-than, and less-than |
| 4-bit Multiplexer         | Multiplies two unsigned 4-bit inputs to produce an 8-bit result     |

## RTL Design

The designs use combinational logic to implement arithmetic operations and comparison functions. Each module is maintained separately to support readability, simulation, and synthesis.

## Simulation and Verification

The `simulation/` directory contains testbenches for the individual designs. These testbenches are intended to check the expected behavior across the supported input combinations.

To run a testbench, compile the relevant RTL module together with its testbench in a compatible Verilog simulator. For example, with Icarus Verilog:

```bash
iverilog -g2005 -o sim_adder rtl/adder.v simulation/tb_adder.v
vvp sim_adder
```

Repeat with the appropriate filenames for the other modules. Simulation results should be checked before describing a design as verified.

## FPGA Implementation Evidence

### RTL and Synthesized Schematics

The `schematic/` directory contains available schematic images documenting the design structure.

### Device Utilization

The `device_utilization_report/` directory contains available FPGA resource utilization reports. These reports can be used to examine the resources consumed by each synthesized design.

### Timing Analysis

The `timing_report/` directory contains available timing reports for examining reported path delays and timing characteristics.

### Power Analysis

The `power_report/` directory is reserved for power reports, if generated by the original design flow.

### Bitstream Generation

The `bitstream_gen/` directory is reserved for genuine FPGA implementation outputs, including a generated bitstream if available. A `.bit` file is a device-specific configuration file and should only be included when its target device and origin are known.

## Constraints

The `constraints/` directory contains UCF files with pin assignments and I/O standards from the original assignment.

These constraints are board-specific. Confirm the target FPGA part, physical pin mapping, and I/O bank voltage before using them for hardware implementation.
